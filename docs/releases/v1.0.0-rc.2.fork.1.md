# PerPay 1.0.0-rc.2.fork.1

本定制源码合入上游至 `a738c6d`，新增全局审计日志、后台弹层与详情重排、二维码失败重试和长金额／短横屏适配。当前未发布定制镜像或创建 Release；源码合并不代表已推送或部署。

## 定制保留

保留按网站向上／向下调整金额，向下从减1分开始，最低应付1分，不增加原价优先逻辑。金额占用、冷却及旧单幂等约束保持原样。桌面、手机和二维码弹窗的精确金额提示及未确认付款提示继续保留；小屏幕和放大文字下说明可独立滚动，二维码保持完整显示。

## 审计与升级

兼容范围24—40；原有迁移1—39的编号、SQL与校验和不变。上游审计迁移39在本 Fork 为40，本 Fork39仍是账号删除状态，不能混用相同 schema 数字的上游与 Fork 数据库。

核心审计与上下文持续保留，运行活动保留30天；旧审计事件及哈希不变，未采集的来源和字段变化不回填。审计导出、数据库及备份需按包含这些信息的数据管理。

升级前保留一致性数据库备份与原 `PERPAY_MASTER_KEY` 主密钥，在隔离副本验证迁移、旧订单、密钥、审计链和恢复。`app`、`backup`、`maintenance` 必须使用同一份支持 Fork schema40 的构建。旧 `1.0.0-rc.1.fork.1` 最高支持39，不能直接打开新库，也不能恢复旧库覆盖升级后的新收款。备份目录内待采集的维护活动文件需一并保管。

参见 [Fork 维护说明](https://github.com/Sark1tama/PerPay/blob/main/docs/fork-maintenance.md)、[定制部署指南](https://github.com/Sark1tama/PerPay/blob/main/docs/deployment.md)和[维护与恢复](https://github.com/Sark1tama/PerPay/blob/main/docs/maintenance.md#固定版本与回滚)。
